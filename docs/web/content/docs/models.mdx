The current source runs a model on the phone to write replies. It searches
enabled libraries and supplies relevant passages to that model. It contains no
hosted inference client. Android device acceptance for this path is pending.

Minimum RAM is the list’s compatibility floor, not a guarantee of a particular speed. Android, other apps, prompt length, temperature, and available memory all affect performance. Installation needs room for the download, verification, and the installed model; follow the space guidance in the app.

## Pick a comfortable starting point

The default is Qwen3.5 2B (Q4_K_M, about 1.28 GB), the official Unsloth GGUF with a declared 262k context window; non-thinking chat is used by default. Phi-4 Mini (Q4_K_M, about 2.49 GB) remains available as a larger alternative. LFM2 1.2B (Q4_K_M, about 0.73 GB, Liquid AI's official GGUF, 128k declared) is the third option and the lightest: on the acceptance emulator it ran a grammar-constrained turn at 50.3 against 92.3 milliseconds per token and held 1.30 against 1.89 GiB of resident memory, which is the figure that matters on a 4 GB phone. Those are emulator numbers from one device; no phone-class measurement exists, so they are not a speed promise. Qwen3.5 2B remains the default on any phone that meets its declared memory floor, and below that floor the welcome recommendation resolves to the model that can actually load there. The current Android rebuild configuration fixes the active native context at 4,096 tokens and the answer budget at 320 tokens; it does not select a larger context from device RAM. A model's advertised context is not allocated in full. These source settings have not yet been validated on a target device.

## Change models

Open **Settings → Models**. Download another compatible option, then select the installed model you want to use. Downloading and switching are separate actions. Remove a model you no longer need to reclaim storage; keep another working model available for chat.

Tap **Check for updates** when connected to refresh the available choices. Opening the screen doesn’t start a background download.

## Bringing a model file

**Add a model file** is available in model settings for local packages. Being a GGUF file does not by itself make a model compatible: architecture, tokenizer, prompt formatting, and memory requirements must also fit the pinned runtime. The in-app choices are the supported starting point.

## Reducing local work

Smaller models, focused questions, and a narrower library scope reduce the
amount of local work requested by the current source. Device measurements are
needed before turning those changes into a speed recommendation. The app has a
Stop control for an active reply; its device behavior is also pending
acceptance.

When the app moves to the background, the current source stops an active reply
but keeps a loaded model for a warm return. Changing the selected model or
explicitly trimming inference memory releases its weights. This lifecycle has
not yet been validated on a target device.
