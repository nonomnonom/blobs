Blobs uses Kotlin and Jetpack Compose for Android, Room and SQLite FTS5 for storage and retrieval, and a pinned llama.cpp CPU runtime for local inference. Python runs on the development computer for corpus preparation, not on users’ phones.

The repository is in a rebuild phase. The current product decision prohibits
builds, tests, benchmarks, and evaluators until the local vertical slice is
ready for validation. The commands below are for the later verification phase,
not evidence that the current rebuild works.

## Build the Android app

When validation resumes, follow the [Android build guide](https://github.com/nonomnonom/blobs/blob/main/android/README.md) for the pinned toolchain, a clone without large corpus downloads, preparation, verification, and installation. App builds and unit tests do not need the reviewed record shards.

When validation resumes, use the [contribution guide](https://github.com/nonomnonom/blobs/blob/main/CONTRIBUTING.md#verification) to choose checks for your change. Asset-dependent performance tools are separate from ordinary application verification.

## Run this website

Use Node.js 24 and npm. From the repository root:

```sh title="Start the documentation site"
cd docs/web
npm ci
npm run dev
```

Open `http://localhost:3000`. The website uses Next.js, Fumadocs, local fonts, and MDX. Edit guides in `content/docs`; `meta.json` controls the sidebar order. Model and library tables read the Android app’s bundled package metadata.

The [website guide](https://github.com/nonomnonom/blobs/blob/main/docs/web/README.md) covers checks, static export, preview, and GitHub Pages hosting at `/blobs`. Set `NEXT_PUBLIC_BASE_PATH` at build time for another subpath, or leave it unset for domain-root hosting.

See [contributing](/docs/contributing) for change ownership and review expectations.
